## 1. Open Source Declaration

`tpt-shipyard` is a fully open-source, MIT-licensed computational engine for **vehicle construction and assembly**: sea shipyards, orbital assembly, in-space manufacturing, and the digital twin of the build process. Every crate, every assembly planner, and every structural solver is freely available under MIT OR Apache-2.0.

### The Core Insight

You identified something profound: **a spaceship built in space does not need to be a rocket.**

On Earth, every spacecraft is constrained by:
- Aerodynamic drag during ascent
- Maximum dynamic pressure (Max-Q)
- Fairing diameter limits (typically 5m)
- Launch vibration and acoustic loads
- Gravity-induced sag during horizontal assembly

In orbit, none of these constraints exist. You can build:
- Rotating habitats (O'Neill cylinders, Stanford torus)
- Kilometer-scale solar power stations
- Arbitrary truss geometries
- Gravity-gradient stabilised structures
- Vehicles optimised purely for vacuum operation

`tpt-shipyard` is the engine that plans, simulates, and validates the construction of these structures — whether in a drydock in Busan or in a robotic assembly bay at Earth-Moon L2.

### Why Fully Open Source?

1. **Sea shipyards** (Hyundai Heavy, Meyer Werft, Fincantieri) run on proprietary planning tools and tribal knowledge. There is no open, auditable digital twin standard for ship construction.
2. **Space assembly** is in its infancy. NASA's Gateway, SpaceX Starship assembly, and commercial station projects are all developing proprietary tooling. An open standard for orbital assembly planning does not exist yet.
3. **The physics gap:** Most structural tools simulate vehicles *in service*. Almost none simulate vehicles *during construction* — where the structure is incomplete, partially welded, and subject to completely different load cases.

## 2. Executive Vision: Build Anything, Anywhere

`tpt-shipyard` is the **construction phase** of the vehicle lifecycle. It sits between design (`tpt-transport`) and operation, managing the transformation of raw materials into a complete vessel.

### The Two Worlds

| Dimension | Sea Shipyard | Space Shipyard |
|---|---|---|
| Gravity | 1g during entire build | Microgravity assembly |
| Atmosphere | Air, wind, rain | Vacuum, thermal extremes |
| Structural loads | Gravity sag, welding distortion | Station-keeping, docking impulses |
| Launch constraint | Must float after launch | No launch constraint if assembled in orbit |
| Shape freedom | Hull must displace water | Arbitrary geometry possible |
| Assembly method | Cranes, welding, block construction | Robotic arms, additive manufacturing |
| Environment | Shipyard, drydock, slipway | Orbital station, Lagrange point |
| Key risk | Launch failure, flooding | Micrometeoroid, thermal cycling |

### Why Rust for Shipyard Simulation?

| Requirement | Rust Advantage |
|---|---|
| Multi-phase structural analysis | Track incomplete structures through 50+ build stages |
| Real-time digital twin | WASM compilation for interactive shipyard dashboards |
| Robotic path planning | Memory-safe motion planning for space assembly robots |
| Enterprise deployment | MIT-only chain, no GPL audit risk for shipyards |
| Concurrency | Parallel simulation of welding sequences |
| GPU acceleration | `wgpu` for visualising assembly sequences in 3D |

pub struct WeightModel {
    pub design_weight_kg: f64,
    pub design_cog: Vector3,
    pub items: Vec<WeightItem>,
}

pub struct WeightItem {
    pub id: ItemId,
    pub name: String,
    pub weight_kg: f64,
    pub cog: Vector3,
    pub status: ItemStatus,
    pub margin_pct: f64,
}

pub enum ItemStatus {
    Design,
    Ordered,
    Received,
    Installed,
    Replaced,
}

impl WeightModel {
    pub fn total_weight(&self) -> f64 {
        self.items.iter()
            .filter(|i| matches!(i.status, ItemStatus::Installed | ItemStatus::Design))
            .map(|i| i.weight_kg)
            .sum()
    }

    pub fn centre_of_gravity(&self) -> Vector3 {
        let total = self.total_weight();
        let weighted_sum: Vector3 = self.items.iter()
            .map(|i| i.cog * i.weight_kg)
            .sum();
        weighted_sum / total
    }

    pub fn weight_report(&self) -> WeightReport {
        // Generate weight report by system/zone
        // Track margins and deviations
    }
}

use tpt_transport::core::Vehicle;

fn plan_construction(vehicle_design: &Vehicle) -> VesselProject {
    // Convert design geometry into buildable blocks/modules
    // Determine construction method based on vessel type
    
    match vehicle_design.vehicle_type {
        VehicleType::Maritime { .. } => {
            // Sea shipyard: block construction, drydock
            plan_sea_construction(vehicle_design)
        }
        VehicleType::Space { .. } => {

        }
    }

use tpt_transport::core::AsBuiltProperties;

fn handover_to_operations(
    digital_twin: &DigitalTwin,
) -> AsBuiltProperties {
    // Transfer as-built properties to operational model
    // Includes:
    // - Actual weight and CoG (not design)
    // - Welding residual stresses
    // - As-built geometry (with distortions)
    // - Quality records
    
    AsBuiltProperties {
        weight_kg: digital_twin.weight_model.total_weight(),
